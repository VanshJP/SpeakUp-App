# Settings

## Purpose

Hub that routes to focused settings surfaces (session, analysis, AI, prompts, weights, calibration, data, etc.).

## Key files

| Role | Path |
|------|------|
| Hub | `SpeakUp/Views/Settings/SettingsView.swift` |
| Pages | `SessionDefaultsView`, `AnalysisSettingsView`, `AIModelSettingsView`, `FeedbackSettingsView`, `PromptSettingsView`, `ScoreWeightsView`, `VoiceProfileView`, `VoiceCalibrationView`, `ReminderSettingsView`, `RoutineSettingsView`, `ProfileSettingsView`, `DataManagementView`, `WordWorkoutSettingsView`, `WordBankView`, `AppearanceSettingsView` (App Look), `RecordingLookView`, `AnalyticsDiagnosticsView` |
| Privacy & data | `SpeakUp/Views/Settings/PrivacyDataView.swift` |
| VM | `SettingsViewModel.swift` |
| Model | `UserSettings.swift`, `SupportLinks.swift` |

## Invariants

1. iCloud toggle flips freely — no paid gate during the beta ([monetization.md](./monetization.md)).
2. Support / privacy / terms URLs from Info.plist (`BT*URL` keys) — hide rows when unset.
3. DEBUG Lifetime override via `EntitlementStore.setDebugOverride` only.
4. Score weights persist on `UserSettings`; defaults in `ScoreWeights.defaults` (`SPEECH.md`). Weights are **relative**: `SpeechService.calculateOverallScore` normalizes them (`ScoreWeights.normalized`), so `ScoreWeightsView` shows each weight as its share of the score and never gates Save on a 100% total (only on at least one non-zero weight). Save rides in a `.safeAreaBar`; drafts start from the stored weights in `init` so the sliders' step haptics do not fire on appear.
5. Sheets from Settings: `.appBackground(.subtle)`. The **hub** has no navigation bar (`.toolbar(.hidden, for: .navigationBar)`, like every root tab) — the row held the word "Settings" above a tab button labelled Settings and nothing else. The hub names itself with `PageTitle` ("Big Talk" / Settings), the header Today and Learn wear; without one it opened on the Practice section header, which read as the page's name. Every pushed sub-page keeps its own `.inline` title and adds `.restoresNavigationBar()` (applied once inside `settingsLink`). Details: [ui-design-system.md](./ui-design-system.md) rule 9.
6. **Hub shape.** Three sections: **Practice** (Session Defaults, Routine, Analysis, Word Workout, Word Lists, Prompts, Session Feedback) → **Appearance** (App Look, Recording Look) → **Account & Data** (Profile, Reminders, AI, iCloud, Data Management) → **About Big Talk**, alone in an untitled group with the version as its accessory. **Each section is one `GlassRowGroup`** - its rows on one plate with hairlines inset past the icon, pressing with `RowPressStyle` - not a card per row: fourteen floating plates made the hub the heaviest page in the app, and History already grouped a week's takes on one plate. `AboutSettingsView` groups its rows the same way. Sub-pages built from `Label` rows (Session Defaults, Analysis, Feedback, Reminders, Prompts, Data Management, Voice Profile, Privacy & Data, Word Workout, Score Weights, About) take `.labelStyle(.row)` on their content so titles start on one line whatever the glyph, and every row has a real symbol - Voice Profile's `waveform.badge.person.crop` does not exist and drew nothing (now `waveform.and.person.filled`). Privacy & Data is pushed, so it has Back and no Done. The display name is **not** a settings category and **not** an inline field on the hub — a bare `TextField` as the first thing Settings shows made the least-touched knob the loudest object on the page. It is one `Profile` row inside Account & Data, opening `ProfileSettingsView`.
    **Sub-pages use the hub's row grammar.** Rows that belong together are one `GlassRowGroup` (never a `GlassCard` split by `Divider()`s), each row at least `AppLayout.minHitTarget` tall, tappable rows pressing with `RowPressStyle` (a scale is for cards and tiles). A row that needs explaining carries a caption under its title, indented to the title column and read to VoiceOver as the control's hint - not a paragraph under the card covering five rows at once. Chevrons only on rows that push; a row that opens an alert or a sheet has none. Row labels are sentence case unless they repeat a nav title ("Voice Profile", "Score Weights").
    **A section header has to earn itself.** "Look" with one row under it was a label with nothing to label. `AppearanceSettingsView` (App Look) and `RecordingLookView` are **siblings** on the hub, one push each — Recording Look used to sit three pushes deep (Look → Appearance → Session look) behind two generic words, which is the wrong depth for the settings people browse for fun. Do not re-nest one inside the other.
    **Rows are icon chips, not loose glyphs** — a 30pt `IconChip`, the same recipe as `ToolCategoryCard` and the iCloud row. Pick hues that read on the disc: Analysis was `categoryNeutralCool`, which all but vanished at 0.18. A column of bare grey symbols is read line by line; a column of tinted chips is scanned. Give each row in a section its own hue. The iCloud row carries no card tint: it was the one row you cannot open and the loudest object in its section.
7. `AppearanceSettingsView` ("App Look") owns app-wide cosmetics: **Glass** (Light / Dark → `UserSettings.glassAppearance`) and **Background** (`AppCanvas` → `UserSettings.appCanvas`). Light glass is the post-brighten default; Dark restores the deeper plate. `ContentView` injects both values into the environment so every `AppBackground` / `GlassCard` reacts without per-screen wiring.
    The Light / Dark control is two miniature pages — current canvas plus a sample plate using that glass — with a selection ring. Do not fill the selected option solid white: that hides the difference the setting is for. Captions stay one line (`previewCaption`); the long `subtitle` is VoiceOver.
    Background tiles are a 2-column grid of equal cards: 96pt swatch, one-line name, two-line subtitle reserved at 32pt so a short description does not shrink the box. The swatch is the control. `CanvasLookView` sets `allowsHitTesting(false)` so a live background cannot steal scroll; picker tiles overlay a clear `contentShape` so tapping the picture selects the look, not only the caption.
8. `RecordingLookView` is the **session** cosmetic picker: one hero preview on top (countdown dial + recording ring on the chosen backdrop), then four labelled grids — background / waveform / record button / timer — persisting `recordingBackdrop`, `waveformStyle`, `recordButtonStyle`, `countdownLook`, `countdownStyle`. Timer Direction (count up / count down) lives here, not in Session Defaults — one dial configured on two screens. No section tabs and no horizontal strips: every option is visible at once. Previews use the real components, never stand-ins. Looks change **form only** — the brand palette is fixed ([ui-design-system.md](./ui-design-system.md)). The backdrop and the timer look both paint the whole session (countdown **and** recording). `RecordingLookPreview` is a full-screen cover that plays countdown → recording; the record button skips ahead, then stops and dismisses. The stored column is still `UserSettings.countdownBackdrop` (schema is additive-only). Base recording backdrop stays classic navy even when the app canvas changes.
9. `soundPack` (Session Defaults → Cue Sound) sets `ChirpPlayer.shared.pack`. Set it in **both** `SettingsViewModel.saveSettings` and `SpeakUpApp.ensureSettingsExist` — the app-boot assignment is what survives a relaunch.
10. `shareCardTheme` is picked in `ShareCardSheet`, not here ([recording-detail.md](./recording-detail.md)).
11. Daily word workout has its own hub row (**Word Workout** → `WordWorkoutSettingsView`), holding `VocabChallengeSettingsCard`: master toggle, words per day, word level (Auto/Easy/Medium/Hard — Auto follows the speaker level, a pin forces one lexicon tier), and "Teach new words". It is not inside `WordBankView` — the workout is the feature and the bank is one of its inputs, so burying the knobs above a word list two levels down had it backwards. `WordBankView` is now **Word Lists** - tabs **Words / Names & terms / Fillers** (`WordListTab` on a `SectionPicker`; "Dictionary" and "bias Whisper transcription" read as jargon) - and stays one tabbed screen. `WordBankView(initialTab:)` lets a caller land on its list: Analysis' "Filler words" row opens Fillers. The input bar is a `.safeAreaBar`, chip ✕ / + buttons are 44pt targets labelled with their word, and resetting fillers asks first. Dictated words go to the tab they were dictated on, even when a tab switch is what stopped dictation. It stays one screen because the three tabs share a pinned bottom input bar and one `DictationService`, so splitting them into separate screens would triplicate both. Dictation takes the session as `.record`, which silences all output, so `DictationService.cleanup()` hands it back as `.ambient` (as `PronunciationService.endGuidance` does) and the view stops dictation on disappear; otherwise "Hear it" in the Word Library and the Read Aloud composer stayed mute afterwards. Additive `UserSettings` fields; default on. The bank / dictionary / spaced-review source flags are still stored but no longer surfaced — always `true`. With "Teach new words" on, an on-device model may quietly top up the fresh-word pool (`VocabFreshWordGenerator`, throttled, safety-validated); the curated lexicon is the permanent fallback. See [vocab-challenge.md](./vocab-challenge.md).

12. Voice profile lives on `VoiceProfileView`, reached from **Analysis**, not Data Management. It is an input to scoring — Auto Pace Target learns from it — not data hygiene, and filing it beside "Clear All Data" hid it. `voiceProfileSampleCount` is a trust weight (a manual calibration sets it to 3), so the UI shows `SettingsViewModel.voiceProfileStatus` - Ready / Learning / Not calibrated - never "trained on N recordings". `DataManagementView` is reset-settings and clear-all-data only, and its hub subtitle says exactly that: there is no export on that screen (journal export is History → Progress → More). Each action reports its outcome on the page (and to VoiceOver), and each dialog names its exact scope:
    - **Reset settings** (`resetSettings`) resets preferences only. Word lists, custom fillers and questions, the voice profile, the learned pace (`calibratedWPM`) and milestone bookkeeping survive, and the queued notification ladder is cancelled with the reminder toggle - it used to keep firing until the next foreground.
    - **Clear all data** (`clearAllData`) deletes recordings and their media, stories and story folders (the shipped folders are reseeded), custom prompts, recording groups, goals, achievements, lesson progress, word lists, custom fillers and questions, saved Read Aloud texts, the voice profile, the learned pace and the usage log - on every synced device when iCloud sync is on, which the dialog and footer say. Settings stay. It then rebuilds the notification ladder so no nudge quotes a deleted streak. Change the dialog and the Privacy & Data FAQ with the scope.

13. **There is no Today Layout row.** Today's layout is edited on Today, in place (toolbar control or long-press), the way every Apple "customize" surface works — Home screen, Control Center, Safari start page. A Settings row that jumped tabs and flipped another screen into edit mode would be a signpost pretending to be a control. See [today-library.md](./today-library.md).

14. **No dead ends.** The hub's AI Features row names the action when nothing is active ("Set up on-device AI"), never "Not available" — the local model is always downloadable, so a state label that only reports the device is noise. Same rule inside `AIModelSettingsView`: the Apple Intelligence card renders only when `appleIntelligenceAvailable` (its badge is then always "Active"); when unavailable the Local AI Model card leads the page, because that is the one card with an action. Deleting the model asks first (it can be a 4 GB download), status badges are `StatusPill`s, and every toggle carries its title for VoiceOver even with `.labelsHidden()`. Every card on that page is one `aiCard` (full width, 16pt padding) with one `cardHeader` (40pt `IconChip`, headline title, caption subtitle); the privacy card used to shrink to its text and sit narrower than the rest. **Download progress stays out of `modelState`.** It lives in `LocalLLMService.downloadProgress` alone (`.downloading` has no payload), only the `ModelDownloadProgress` row reads it, and the URLSession delegate forwards a tick only when it is a 0.5% step *and* 250 ms after the last (`isProgressStep`, pinned in `LocalLLMDownloadTests`). Progress in the state enum re-rendered every view reading `isModelReady` / `LLMService.isAvailable` on each chunk. `isModelDownloaded` and `modelFileSize` read a stored `modelFileBytes` that `refreshModelFile()` updates on download, delete, profile change and a failed load, never the disk from `body`.

15. **Every hub subtitle names an action, not a value.** "Choose take length, countdown, and goal", "Turn on a daily practice reminder", "Add words, names, and fillers" — never "1 min, 15 sec countdown" or "8 categories". A settings list of current values reads like a report; a list of actions reads like doors. The only state a row may show is the one that picks the verb (Reminders and Word Workout flip between "Turn on…" and "Change/Adjust…"). About is the last row, in a group of its own. **Cosmetic rows are the exception, and they show the value twice**: App Look and Recording Look each carry a live `lookSwatch` accessory plus a value subtitle ("Aurora · Rings"), because for a look the current setting *is* the affordance — no verb tells you what your backdrop is. Swatches lay out at 320pt and draw at `scaleEffect(0.2)`; a canvas rendered straight into a 52pt box collapses to a flat rectangle for every option.
16. **The Routine row edits the chain, not the run.** `RoutineSettingsView` is add / remove / reorder only — starting a step happens on Today, where the card lives. The take has no remove control at all rather than a disabled one: a greyed button invites the tap that explains why it cannot be tapped. See [routine.md](./routine.md).
17. **Reminders show a learned time, not a picker.** With `adaptiveReminderEnabled` on (the default) the time row is a readout of what `PracticeRhythm` derived, and "Set the time myself" is the one control that takes it back. A picker the scheduler overwrites every morning is a lie; this is the exception rule 15 does *not* cover, because the value here is not the affordance — the toggle above it is. See [retention.md](./retention.md).
18. **Reminder consent is the whole notification channel, and the screen says so.** `dailyReminderEnabled` gates every class — daily nudge, streak rescue, comeback ladder, milestones. Off means nothing ships. On means the user also sees three per-class toggles and a plain statement of the ceiling (three in a day, and only with a week-long streak on the line). The screen must never promise a narrower contract than the code sends, nor mention controls it is not showing. Turning the toggle on is the moment iOS is asked (`saveSettings` passes `requestPermissionIfNeeded` only then). When iOS will not deliver (`SettingsViewModel.notificationsBlocked`), the screen says "Notifications are off" with **Allow** (never asked - e.g. reminders synced on from another device) or **Open Settings** (denied), and re-checks on return to the foreground. See [retention.md](./retention.md).
19. **Prompt categories are the Prompts page's job, so they are listed open**, one `GlassRowGroup` with the on-count in the header. The last category on cannot be switched off (`toggleCategory` returns `false`); the tap gets a warning haptic and the footer says why, instead of a selection haptic for nothing. Library → Prompts owns browse and search; this page only points there.
20. **Session Feedback:** built-in questions (`DefaultFeedbackQuestions`) are always asked and are labelled "Built in"; only custom questions have a remove control. Making them removable needs an additive `UserSettings` field plus the consumers in `RecordingView` and `RecordingDetailView`, which build the list themselves. The add sheet is a form: Cancel / Add in the bar, Return adds, the field is focused on open.
21. **Usage Diagnostics** exports through a `ShareLink` to a file written on appear (and after Clear); empty metrics read "–".
